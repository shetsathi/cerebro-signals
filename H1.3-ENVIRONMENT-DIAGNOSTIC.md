## ROOT CAUSE

### Issue: Dotenv Not Loaded

The `.env` file EXISTS and contains VALID credentials, but the Node.js process NEVER reads it.

**Why:**
1. `.env` is a plain text file that Node.js doesn't automatically load
2. The script must explicitly load .env via dotenv library
3. The project does not have dotenv as a dependency
4. The script never calls dotenv loading code

**Result:**
- `process.env.ANGEL_ONE_API_KEY` = undefined
- `process.env.ANGEL_ONE_CLIENT_CODE` = undefined
- `process.env.ANGEL_ONE_PASSWORD` = undefined
- `process.env.ANGEL_ONE_TOTP_SECRET` = undefined

**Therefore:**
- `hasAngelOneCredentials()` returns false
- Script exits at Step 1
- Credentials reported as "not configured"

### This is Correct Behavior

✅ The error message is accurate: Credentials ARE configured in .env, but NOT exposed to the script's runtime environment.

✅ The failure is safe: Script doesn't attempt to fabricate data; it fails gracefully.

## RECOMMENDED FIX

### Minimal Solution: Load dotenv in Acquisition Script

**Location:** `src/scripts/h1-full-acquisition.ts`

**Change Required:** Add dotenv loading at the very top (before any other imports)

**Option A: Using dotenv package (requires installing dotenv)**
```typescript
import 'dotenv/config';  // Load .env before other imports

import { AngelOneHistoricalFetcher } from '../adapters/angel-one-historical-fetcher';
// ... rest of imports
```

Then:
```bash
npm install dotenv
```

**Option B: Manual .env loading (no external dependency)**
```typescript
import * as fs from 'fs';
import * as path from 'path';

// Load .env manually before other imports
const envPath = path.join(process.cwd(), '.env');
if (fs.existsSync(envPath)) {
  const envContent = fs.readFileSync(envPath, 'utf-8');
  envContent.split('\n').forEach(line => {
    if (line && !line.startsWith('#')) {
      const [key, ...valueParts] = line.split('=');
      const value = valueParts.join('=').trim();
      if (key.trim()) {
        process.env[key.trim()] = value;
      }
    }
  });
}

import { AngelOneHistoricalFetcher } from '../adapters/angel-one-historical-fetcher';
// ... rest of imports
```

**Recommendation:** Option A (using dotenv) is simpler and standard practice. dotenv is a widely-used, well-tested library.
